# Architecture Review

Analyze the repository architecture without modifying any files.

Evaluate the repository as a software system (application, library, platform, or documentation-driven engineering project), not as a marketing page.

Review the architecture using the following criteria:

- Repository organization
- Directory structure
- Separation of concerns
- Module and boundary clarity
- Scalability
- Maintainability
- Consistency
- Naming conventions
- Documentation architecture
- Relationship between repository artifacts
- Testability and operational readiness (as evidenced in-repo)
- Future extensibility

Do not rewrite the repository.

Do not propose implementation patches in this review pass.

Do not redesign the architecture unless asked in a later task.

Only provide an objective architectural review based on repository evidence.

At the end include:

- Architectural Strengths
- Architectural Weaknesses
- Missing Architectural Components
- Structural Risks
- Scalability Assessment
- Maintainability Assessment
- Overall Architecture Rating (1–10)
